# P4 → P5: M1b baseline pointwise log-likelihood (6,489 games)

Exported 2026-11-24. This handoff reuses the **original-prior constant-tau baseline**;
`s ~ Uniform(0.5,3)`. It is not the s-upper-6 sensitivity model. No model was
refitted, no holdout was used, and no three-model WAIC or ranking was computed.
P5 is responsible for the final WAIC/Delta-WAIC aggregation and interpretation.

## Files and interface

- [pointwise_loglik_share.rds](pointwise_loglik_share.rds): gzip-compressed RDS,
  **500 draws × 6,489 games**, natural logarithms. Same five core fields as the
  current P2/P5 RDS: `ids`, `draw_index`, `loglik`, `convention`, `train_md5`.
  Additional hash/provenance fields explain sources and newline differences.
- [train_game_ids.csv](train_game_ids.csv): one `id` column in matrix column order.
- [draw_index.csv](draw_index.csv): one row per exported matrix row.
- [ids_alignment.csv](ids_alignment.csv): exact ordered comparison with P2 JAGS,
  P2 Gibbs and P5 RDS IDs and their training-ID CSVs. All pass.
- [source_checksums.csv](source_checksums.csv): full-byte hashes of the training
  CSV (working copy and canonical Git LF blob), saved source likelihood, fitted
  inputs and actual fitted JAGS model.
- [numerical_spotchecks.csv](numerical_spotchecks.csv), [validation.txt](validation.txt):
  independent numerical checks, dimensions/finiteness, index checks and reread.
- [file_checksums.csv](file_checksums.csv): exported file byte sizes and SHA256;
  excludes itself to avoid a circular checksum. These are the exact repository
  blob bytes: binary RDS bytes are unchanged, text uses Git's canonical LF form.
  On a Windows CRLF checkout, hash `git show HEAD:path/to/file` bytes for text,
  or download the raw GitHub file; do not expect CRLF text hashes to equal LF.
- [export script](../../../code/P4/M1b_export_WAIC_6489.R).

Usage by P5 (base R only; no fitting/JAGS required):

```r
p4 <- readRDS("outputs/P4/M1b_WAIC_6489/pointwise_loglik_share.rds")
ids <- read.csv("outputs/P4/M1b_WAIC_6489/train_game_ids.csv")$id
stopifnot(identical(dim(p4$loglik), c(500L, 6489L)),
          identical(as.character(ids), colnames(p4$loglik)),
          all(is.finite(p4$loglik)), !anyDuplicated(ids))
# Pass p4$loglik (draws x games) and p4$ids to your unified WAIC workflow.
```

## Selection and original indices

The existing local `baseline_development/pointwise_loglik.rds` contains 1,000
saved rows and real `(chain, iteration)` mappings generated by
`M1b_inference.R::m1b_latent_output`. Its chain counts are 236/251/263/250 and it
contains 969 distinct parameter-row pairs (the original export sampled with
replacement). We do not invent or interpolate missing indices.

For each chain, retain the first saved occurrence of each `(chain, iteration)`;
using **seed 20261124**, RNG `Mersenne-Twister/Inversion/Rejection`, sample 125
rows without replacement, then sort within chain by iteration. Concatenate chains
1–4. All 500 exported parameter pairs are distinct. This balances the subset of
the **existing 1,000 rows**; it does not generate new posterior draws from the
full 16,000 parameter records. Preserve Monte Carlo uncertainty in comparisons.

`iteration` is the **1-based retained row in the original chain matrix** (1–4000),
not a raw JAGS iteration including adaptation/burn-in. `source_loglik_row` maps
to the original 1,000-row likelihood file. `pooled_retained_index` is
`(chain-1)*4000 + iteration`. No original parameter or likelihood file is modified.
The source fit used 2,000 adaptation + 2,000 burn-in and 4,000 retained draws per
chain; source seeds and diagnostics remain in the original baseline directory.

Fit implementation source commit:
`dab0f291adfc0a8755f45b6b4f7194a89bbc2a7b`. Its model and inference blobs were
verified unchanged in the export base `e33651a` (latest main at export start).
Artifact hashes, rather than a claim that ignored RDS files live in that commit,
identify the actual fitted inputs and likelihood used here.

## Exact likelihood convention

Let `y_i=average_i`, `n_i=users_rated_i`, `X_i` be the saved training design, and
`k_i=1` for a credited, named training designer, otherwise 0. For posterior draw b:

\[
\mu_i^{(b)}=\alpha^{(b)}+X_i\beta^{(b)}+k_i u_{d(i)}^{(b)},\qquad
V_i^{(b)}=(\tau^{(b)})^2+(s^{(b)})^2/n_i+(1-k_i)(\sigma_d^{(b)})^2,
\]
\[
\ell_{bi}=\log N(y_i\mid\mu_i^{(b)},V_i^{(b)})
=-\tfrac12[\log(2\pi)+\log V_i^{(b)}+(y_i-\mu_i^{(b)})^2/V_i^{(b)}].
\]

- Observation/pointwise unit: **one game's average rating**, conditional on its
  rating count and covariates. `tau` is constant residual between-game latent SD;
  `s` is shared rating SD; `sigma_d` is designer-effect SD.
- Game latent rating theta has been **integrated out** analytically.
- For 5,866 named-designer games, use that draw's posterior `u[d]`, with designer
  prior `N(0,sigma_d^2)`. **Do not integrate these named effects again.**
- For 623 missing/uncredited games, independent unknown designer effects were
  already integrated, adding `sigma_d^2`. They are not one shared anonymous group.
- These are log likelihood values, not posterior density (no prior terms),
  `-2*loglik` deviance, or simulated/predicted rating values.
- Target: the current **game-level conditional WAIC**. It is not an entire
  unseen-designer-group extrapolation or grouped leave-designer-out evaluation.
  The named designer effects were estimated using training outcomes; the
  conditional versus integrated designer target must accompany reported results.
- P5 M1a integrates theta but has no designer effects and an intercept-only mean;
  M0 is Normal regression without a game theta hierarchy and has its own noise
  and preprocessing assumptions. Aligned IDs do not erase those differences.
  A score difference cannot isolate the independent contribution of covariates,
  designer pooling, observation variance, or any single component.

## Validation and regeneration

1,292 draw/game cells (including named/anonymous games and extreme rating counts)
were independently evaluated with the scalar Normal log formula from original
parameter chain rows. Maximum absolute difference: **8.8817841970012523e-15**,
below 1e-10. The output RDS was reread and its entire payload compared exactly.
All three peer matrices and their IDs were read from actual uploaded files, even
though P5's current README still describes its binary as pending; peers were not
modified. No final WAIC was computed here.

The script requires the original **local-only** baseline `pointwise_loglik.rds`,
`inputs.rds` and `chain_1.rds`–`chain_4.rds`; they remain ignored and are not in
this PR. Consumers need only the shared file. On the original machine, from repo
root, with the same training working bytes, run:

```powershell
Rscript --vanilla code/P4/M1b_export_WAIC_6489.R
```

It reuses the checked-in `source_checksums.csv`, fails if training bytes differ,
and regenerates the same selected rows/CSV evidence without fitting. On another
machine, first validate the local originals against the source hashes and use
their actual training bytes; a clean clone cannot regenerate the full posterior
from summaries alone. New hashes after intentional transport changes must be
reported explicitly. `file_checksums.csv` can be independently checked with
PowerShell `Get-FileHash -Algorithm SHA256` or Python `hashlib.sha256`.

Existing diagnostics and scientific caveats remain in [P4's report](../README.md):
simulation theta interval undercoverage, PPC discrepancies and s-prior sensitivity
are not resolved merely by passing chain diagnostics. This handoff does not change
the model specification or the likelihood to pursue artificial comparability.
